# 极简探针主题（minimal）

monitor 探针的公开状态页主题。纯静态 SPA，**零依赖、零构建**——整个主题就是 `minimal/dist/index.html` 一个文件。

公开页一屏之内给出四类信息：

| 位置 | 内容 |
| --- | --- |
| 汇总条 | 在线节点数 / 可用率、平均延迟、本月流量、按周期折算的月支出 |
| 节点卡片 | 在线状态与运行时长、**延迟检测块**（每路探测一行：名称 + 近 1 小时曲线 + 当前值 + 丢包率）、CPU / 内存 / 硬盘三条占用、实时上下行速率、**费用**（周期、月均、到期倒计时）、流量统计一行 |
| 详情页 `/node/{id}` | **费用明细**（价格、折合月均、到期倒计时、计费模式、配额与重置日）、**网络延迟检测**（多路探测曲线 + 每路当前/平均/最低/最高/丢包）、资源趋势（CPU / 内存 / 磁盘 / 网络）、基础信息 |
| 其它 | 明暗双色（跟随系统，可手动切换）、`/node/{id}` 可刷新可分享、移动端单列自适应 |

## 卡片布局

卡片的纵向顺序，以及为什么这么排：

```
┌──────────────────────────────────────────────┐
│ ● 节点名  [地区]                  在线 14 天 │   ← 在线徽标带淡绿底
│ 系统 · 虚拟化 · 架构             160 天后到期 │
├──────────────────────────────────────────────┤
│ 延迟检测                          近 1 小时 │   ← 主视觉，每路一行
│  ● 电信 163    ╱╲╱╲╱╲           39 ms  0%   │   ← 蓝
│  ● 联通 4837   ╲╱╲╱╲╱           31 ms  2%   │   ← 橙
│  ● 移动 CMIN2  ╱╲╱╲╱╲           45 ms  0%   │   ← 紫
├──────────────────────────────────────────────┤
│ CPU 2 核        内存          硬盘           │   ← 三条占用，各有一色
│ 0.37 0.00 0.00  0.66/2.00 GB  11.6/40.0 GB  │
│ ▓░░░░░░         ▓▓░░░░░       ▓▓▓░░░░       │
├──────────────────────────────────────────────┤
│ ↓ 4.8 MB/s  ↑ 1.8 MB/s       月付 ¥68.00/月 │
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │   ← 配额进度，2px，青色
│ 流量 3.32 / 500.00 GB · 0.7%  累计 ↓146 ↑43.5│   ← 压成一行
└──────────────────────────────────────────────┘
```

**三路探测共用同一个纵轴范围**。各自归一化的话，37 ms 和 110 ms 会被画成一模一样的形状——而三网并排展示的全部意义就是看出哪一路更差。每路配一个与曲线同色的圆点做识别，名称保持中性：三行彩色文字反而不好认。

**丢包率一律显示，0% 也占位**。只给有丢包的行加标记的话，那一行会多出一段宽度，三行的时延数值就参差不齐了。时延与丢包各自固定宽度右对齐，0% 用浅灰、有丢包才转红。

卡片上最多列 3 路探测（`CARD_PROBES`），多出来的在详情页看。列表要的是「通不通、多快」，不是完整的多路曲线。

列表页取延迟时用 `points=60`：迷你曲线只有一百来像素宽，按设备像素宽度去要会让每个节点都发一次大响应。

卡片内容密度较高（三路延迟 + 三条占用 + 速率费用流量），所以网格最多排三列，断点在 780 / 1140 px，以保证占用条的数值不被截断。

## 配色

图表色板 `--c1`…`--c5` 按可辨识度排序，前三个是蓝 / 橙 / 紫——深浅两种主题下都能一眼分开，绿和红留给「在线」与「告警」的语义，所以探测色不占用它们。色板在 `:root` 与 `html.dark` 各定义一份，深色下整体提亮。

| 元素 | 用色 |
| --- | --- |
| 汇总磁贴 | 顶部 3px 色条 + 同色圆点：在线绿 / 延迟蓝 / 流量青 / 支出紫 |
| 在线徽标 | 淡绿底 + 绿字；待上报为琥珀色 |
| 探测圆点与曲线 | `--c1` 蓝、`--c2` 橙、`--c3` 紫，依次往后 |
| 占用条 | CPU 蓝、内存绿、硬盘紫；≥75% 转琥珀、≥90% 转红 |
| 配额进度条 | 青色；≥75% 琥珀、≥90% 红 |
| 详情页面板标题 | 左侧 3px 色条，按面板区分 |

底色本身保持克制（浅色 `#f4f6f9`，深色 `#0a0b0e`），色彩都落在数据本身上。

## 安装

**方式一**：把 `theme.tar.gz` 拖进后台「主题」页。

**方式二**：把 `minimal/` 目录整个放进 hub 的 `--themes` 位置（一键脚本装出来的是 `/opt/monitor/data/themes/`），然后在「主题」页选中，无需重启。

选中的主题缺失或损坏时，hub 会自动回落到内置默认主题。

> **归档布局**：`theme.tar.gz` 的**根目录就是主题目录的内容**——`theme.json`、`preview.png`、`dist/` 平铺在归档根上，**没有外层目录**。hub 会把它解到 `<themes-dir>/<short>/`。多套一层目录会导致安装后的主题缺 `theme.json`。`dev/package.mjs` 会校验这一点。

## 本地预览

没有真实 hub 也能看效果。`dev/mock-server.mjs` 用纯 Node（无第三方依赖）模拟了 hub 的全部四个同源接口，含手写 WebSocket 握手与文本帧：

```bash
node dev/mock-server.mjs --port 9911     # 打开 http://127.0.0.1:9911/
```

参数：

| 参数 | 用途 |
| --- | --- |
| `--freeze` | WS 只推一次就静默，便于无头浏览器截图时页面进入空闲 |
| `--nows` | 拒绝 WebSocket 升级，强制主题走 5 秒轮询的降级路径 |
| `--closed` | 头 1.5 秒假装公开页可用，之后 `/api/nodes` 一律 401、`/api/me` 改口 `public_page: false`，用来验证运行期关闭时主题会重查 `/me` 并跳转后台 |
| `?dark=1` | 以深色模式启动（无头浏览器改不了 `prefers-color-scheme`） |

对着真实 hub 开发时，起一个 hub 实例即可（主题侧无需代理配置，因为本主题不跑 Vite）：

```bash
monitor-hub --listen 127.0.0.1:9911 --db /tmp/monitor.db --site http://127.0.0.1:9911
```

## 开发与校验

```bash
node dev/test.mjs        # 纯函数自测，失败退出码非零
node dev/package.mjs     # 校验 theme.json / 目录名 / 体积上限，然后打包
```

`dev/test.mjs` 的做法是给主题脚本喂一个最小 DOM 桩后整体求值，因此不需要测试框架，也不需要把函数拆成模块——脚本顶层声明在 vm 里会挂到全局对象上，直接取来调用即可。覆盖：数字格式化与时长换算的边界（0、负数、小数、NaN、缺字段）、费用折算与多币种分组、延迟样本分组与迷你曲线、坏数据降级、地区码与坐标轴取整。

## 接口契约

只用这四个同源接口，全部按「这个 key 可能不存在」处理：

| 接口 | 用途 |
| --- | --- |
| `GET /api/me` | 站点名、登录状态、公开页开关 |
| `GET /api/nodes` | 节点列表、实时指标、累计流量 |
| `GET /api/nodes/{id}/metrics` | 历史指标与延迟记录 |
| `GET /api/ws` | 每 2 秒推送一次节点快照 |

`metrics` 的三个查询参数都用到：

- `hours=N` 窗口宽度，延迟取 1/6/24 小时，资源取 1/6/24 小时与 7 天
- `points=W` 按设备像素宽度上报，只让 hub 抽得更稀
- `series=metrics|ping` 分开取，省掉不画的那一半

丢包率取自响应的 `loss`（整个窗口，按探测 id 给百分比），**不是**拿样本行里的 `loss` 自己平均——那是所在桶的百分比，除数已经丢了。探测曲线的名字取自响应的 `probes`，因此画延迟图不需要第二个请求，也不需要管理员身份。

## 三种状态的降级

| 状态 | 表现 |
| --- | --- |
| 离线（`metrics: null`） | 状态点变灰，显示「离线 x 小时」，占用条留空但保留机器规格 |
| 已连接未上报（`online: true` + `metrics: null`） | 显示「已连接 · 待上报」与「正在等待第一次上报」，区别于从未接入的节点 |
| 坏数据（字段缺失或类型不对） | 入口处做一次完整指标校验，不合格只把该节点的 `metrics` 置空并显示「不可用」，不让一个节点的坏数据把整页白屏 |

另外，公开页在标签页打开期间被关闭时，主题会重查一次 `/api/me`；确认已关闭且无人登录就把访客送去 `/admin/`，而不是留在一个不再更新的列表上。

## 与默认主题的差异

- 不依赖 React / Vite / shadcn，单文件交付，没有构建期变量，克隆下来直接改
- 列表页就带延迟检测，且**每路探测一行**（三网就是三行）并共用纵轴、一色一路，默认主题只在详情页画延迟
- 汇总条直接给「平均延迟」和「月支出」；费用明细在详情页单独成块
- 流量统计在卡片上压成一行，不再占一个占用条
- 多币种不合并：hub 不提供汇率，把 USD 和 CNY 相加会得到一个不存在的数，因此分币种并列显示
- 国家码映射为中文名（含中国香港 / 中国澳门 / 中国台湾的正确表述），未收录的代码原样显示
